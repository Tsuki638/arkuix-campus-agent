# 基于 ArkUI-X 的跨端 AI Agent 项目

围绕大学生学习或生活中的具体需求，使用 ArkUI-X 的同一套业务与 UI 代码，完成鸿蒙与 Android 两端的 AI Agent 应用。项目包含真实大模型调用、多轮任务或工具执行、文本对话、鸿蒙语音和本地会话历史。

## 四人分工总览

| 成员 | 负责部分 | 核心工作 | 主要交付物 |
| --- | --- | --- | --- |
| 成员 A | Agent 核心 | 任务流程、上下文管理、工具调用、状态与失败处理 | Agent 引擎、场景工具、流程说明及验证用例 |
| 成员 B | 共享 UI 与交互 | 对话页面、历史管理、结果展示、设置及语音入口 | 共享页面与组件、交互反馈、双端页面验证记录 |
| 成员 C | 模型与数据服务 | 云端模型接入、请求与响应适配、本地历史持久化 | 模型适配器、会话仓库、服务配置及数据验证说明 |
| 成员 D | 平台能力与工程交付 | 工程环境、鸿蒙 ASR/TTS、权限适配、双端构建与安装 | 平台适配、语音链路、构建配置、安装包及运行说明 |

## 全体成员需要准备的环境

| 环境或资源 | 用途与准备要求 |
| --- | --- |
| Git 与 GitHub 账号 | 克隆仓库、创建分支、提交代码、发起 Pull Request 和处理合并冲突。 |
| DevEco Studio | 编辑 ArkTS 与 ArkUI 页面，进行工程同步、调试和鸿蒙应用构建。 |
| HarmonyOS SDK 与 ArkUI-X SDK | 由成员 D 确认兼容版本，团队使用同一组版本和编译目标。 |
| Node.js 与 npm | 共享逻辑检查使用 Node.js 22.13 或以上版本；DevEco 与 ACE 构建所用 Node 按 SDK 配套要求配置。 |
| Android SDK 与匹配的 JDK | 由成员 D 主导配置，用于 Android 构建、安装和调试；参与双端联调的成员按需安装。 |
| 测试设备 | 准备可安装调试的鸿蒙设备与 Android 设备或模拟器；鸿蒙语音需要验证麦克风授权、识别和播报。 |

SDK、IDE、JDK 和构建工具的版本由成员 D 统一记录，其他成员按相同组合配置。环境搭建参考 [ArkUI-X 官方 ACE Tools 快速指南](https://github.com/arkui-x/docs/blob/master/zh-cn/application-dev/quick-start/start-with-ace-tools.md)。

全体成员应掌握以下基础知识：

- TypeScript / ArkTS 的类型、接口、类、模块导入与异常处理。
- `Promise`、`async/await`、JSON 数据结构与 HTTP 请求的基本用法。
- Git 分支、提交、拉取、Pull Request 和合并冲突处理。
- ArkUI-X 共享业务与平台适配的边界，以及公共接口变更对其他模块的影响。

## 成员 A Agent 核心

### 具体工作

1. 与团队确定具体场景，写清用户输入、需要澄清的条件、工具动作和任务完成标准。
2. 实现 Agent 执行流程：接收输入、读取上下文、请求模型、执行工具、回传结果和生成答复。
3. 管理多轮上下文，使后续任务能够使用之前的信息；缺少条件时向用户提问。
4. 实现至少一个实用的场景工具，定义名称、参数 schema、参数校验和结果格式。
5. 提供思考中、执行工具、完成和失败状态；处理未知工具、非法参数、模型失败、循环上限与并发发送。
6. 与成员 B、C 联调，编写流程与失败处理说明，准备成功、澄清和失败场景的验证用例。

### 需要准备的环境

- Node.js 与可编辑 TypeScript / ArkTS 的开发工具，用于独立验证 Agent 逻辑。
- 模拟的模型、工具与会话接口，用于独立开发和验证任务流程。
- 团队统一的 DevEco / SDK 环境，用于应用内联调。

### 需要掌握的知识

- Agent 与普通聊天的区别，任务拆解、条件澄清与结束条件设计。
- 多轮上下文、提示词、工具调用及 JSON Schema。
- 状态机、异步控制流、错误传播和执行次数限制。
- 接口抽象、依赖注入，以及使用模拟依赖验证业务逻辑的方法。

### 负责目录与完成标准

主要目录：`app/entry/src/main/ets/agent/`。

完成标准：能够展示多轮任务推进或完整的工具执行过程；缺少信息时能够澄清；工具失败与执行超限时给出明确反馈，并提供对应验证用例。

## 成员 B 共享 UI 与交互

### 具体工作

1. 实现文本对话页面，包括输入、发送、消息列表、滚动和等待状态。
2. 展示 Agent 任务进度、工具执行结果和失败反馈，按场景设计结果卡片。
3. 实现会话列表、新建、切换、回看和删除确认，对接统一的会话仓库。
4. 提供模型配置入口，与成员 C 对接接口地址、模型名称和运行时密钥。
5. 对接成员 D 的语音接口，提供语音输入、录音反馈、播报与停止入口。
6. 统一页面视觉，补齐空态、输入校验和错误提示；在两端检查键盘、长文本、布局和主要操作。

### 需要准备的环境

- DevEco Studio 与团队统一的 HarmonyOS / ArkUI-X SDK，用于页面开发和调试。
- 鸿蒙测试设备，以及用于 Android 页面联调的设备或模拟器。
- 任务样例、会话数据和模拟接口；使用草图或熟悉的设计工具整理页面原型。

### 需要掌握的知识

- ArkUI 声明式界面、基础组件、布局与列表渲染。
- 状态管理、组件通信、页面生命周期和异步界面更新。
- 输入交互、加载反馈、空态、异常提示与基础视觉设计。
- UI 与业务逻辑的分离，以及通过接口对接 Agent、历史和语音能力的方法。

### 负责目录与完成标准

主要目录：`app/entry/src/main/ets/ui/`、`app/entry/src/main/ets/pages/` 及共享 UI 资源。

完成标准：两端使用同一套页面代码完成主要操作；任务状态和异常可见；用户可以完成文本对话、查看结果和管理历史；语音不可用时仍可使用文本。

## 成员 C 模型与数据服务

### 具体工作

1. 选择至少一种可用的云端大模型服务，验证真实对话与项目所需的工具调用协议。
2. 实现统一模型适配层，处理消息格式、工具定义、调用 ID 与工具结果回传。
3. 接收界面的运行时配置，处理鉴权失败、限流、超时、空回复和异常响应。
4. 控制请求上下文长度，实现会话保存、查询、排序、回看和删除，管理本地数据格式及版本。
5. 处理写入失败、数据损坏与版本不兼容；在两端验证退出重启后的历史恢复和删除结果。
6. 向成员 A、B 提供稳定的模型与仓库接口，整理服务配置、模型来源和数据验证说明。

### 需要准备的环境

- 可用的模型服务账号、API Key、模型名称和官方 API 文档。
- 能访问所选服务的网络环境，以及用于检查请求和响应的接口调试工具。
- Node.js、模拟 HTTP / 存储接口，以及用于验证文件读写的 DevEco 和双端运行环境。

### 需要掌握的知识

- HTTP / HTTPS、请求头、鉴权、JSON 解析和常见状态码。
- 大模型消息格式、上下文窗口、Token 概念与工具调用协议。
- 本地文件或轻量数据库、数据序列化、并发写入和持久化恢复。
- API Key 的运行时配置、日志中的敏感信息处理，以及服务层的错误封装。

### 负责目录与完成标准

主要目录：`app/entry/src/main/ets/services/model/`、`app/entry/src/main/ets/services/storage/`。

完成标准：两端能够调用真实模型；模型消息与工具结果正确配对；会话重启后可回看，删除后重启不再出现；请求及存储失败可反馈到界面。

## 成员 D 平台能力与工程交付

### 具体工作

1. 统一 DevEco、HarmonyOS SDK、ArkUI-X SDK、ACE Tools、Android SDK 和 JDK 的版本与路径配置。
2. 配置 ArkUI-X 工程与平台宿主，尽早验证同一共享模块能构建并启动鸿蒙与 Android 应用。
3. 检查系统网络、文件和其他 API 的跨平台支持，处理必要的权限及插件配置。
4. 实现鸿蒙语音识别 ASR：申请麦克风权限、识别语音、返回文本，并处理拒绝、取消和失败。
5. 实现鸿蒙语音播报 TTS：播报模型答复、支持停止，并在退出页面时释放资源。
6. 隔离平台专有依赖，配置签名与安装步骤，完成双端联调，汇总环境版本、安装包和演示材料。

### 需要准备的环境

- DevEco Studio、配套 SDK、ACE Tools 和 OHPM，并配置所需环境变量。
- Android SDK、匹配的 JDK、Android 构建工具与调试工具；按需使用 Android Studio 管理 SDK 和模拟器。
- 鸿蒙真机、Android 真机或模拟器，以及设备调试连接与签名所需的账号和配置。
- 所选鸿蒙语音能力的官方文档、SDK 与测试环境。

### 需要掌握的知识

- ArkUI-X 工程结构、共享模块、原生宿主与平台适配方式。
- HarmonyOS 与 Android 的构建、签名、权限、安装与日志调试。
- ASR、TTS、麦克风授权、异步回调和资源生命周期管理。
- 平台 API 兼容性检查、构建错误排查，以及可复现的环境与运行说明编写。

### 负责目录与完成标准

主要目录：`app/entry/src/main/ets/platform/`、`scripts/` 及原生工程、宿主和构建配置。

完成标准：同一代码库可在两端构建、安装和运行；鸿蒙完成“语音识别 → Agent 与模型 → 语音播报”；权限拒绝与停止行为可处理，构建和安装步骤可复现。

## 模块交接与协作要求

| 提供方 | 使用方 | 交接内容 |
| --- | --- | --- |
| 成员 A | 成员 B | Agent 调用入口、执行状态和任务结果。 |
| 成员 A | 成员 C | 工具名称、参数 schema 与工具执行结果格式。 |
| 成员 C | 成员 A | 统一模型接口与模型异常反馈。 |
| 成员 C | 成员 A、B | 会话仓库接口及本地数据结构。 |
| 成员 D | 成员 C | 系统 HTTP 适配、权限及文件 API 支持情况。 |
| 成员 D | 成员 B | 统一语音接口、可用状态与识别播报结果。 |

- 公共接口位于 `app/entry/src/main/ets/contracts/`，依赖装配位于 `app/entry/src/main/ets/bootstrap/`；修改前同步相关成员。
- 开发分支分别使用 `feat/agent`、`feat/ui`、`feat/services`、`feat/platform`，通过 Pull Request 合并到 `main`。
- 每个模块提交代码、使用说明及对应验证结果；共享逻辑修改执行 `npm run check`，平台与 UI 修改提供设备或构建验证记录。
- 核心业务与 UI 使用同一套代码，平台差异集中在适配层和工程配置；密钥、签名证书与本机路径通过本地或运行时配置管理。
