### 5.1 鸿蒙真机

> **动手前的 4 个前置条件**（缺一个就会白忙）：
> 1. 华为账号已完成**个人开发者实名认证**（`developer.huawei.com/consumer/cn` → 账号中心 →

> 2. **本机系统时间与北京时间 UTC/GMT+8 一致**——官方签名文档明确「如果不一致，将导致签名失败」。
>    本机 2026-11-13 实测 `China Standard Time / UTC+08:00`，W32Time 服务 Running，已满足。
> 3. 手机 HarmonyOS 版本对应的 API ≥ 24（工程 `compatibleSdkVersion: 6.1.1(24)`）。

1. 确认系统版本：设置 → 关于本机，查看 HarmonyOS 版本 / API 版本；把型号、系统版本、

5. 电脑验证（DevEco 装完后，hdc 实际路径以安装结果为准）：

   看到设备 UDID 才算连通；`[Empty]` 说明线/授权/驱动没过：换数据线、

### 5.2 自动签名（关键，必须账号）

依据官方 [创建和运行 Hello World](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V5/ide-hello-world-V5)
与[为应用/服务进行签名](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides-V2/signing-0000001587684945-V2/)
的自动签名章节，顺序是：

1. DevEco Studio → `File > Open`，选 **`E:\arkuix-campus-agent-C\app`**（是 `app/` 目录，
   **不是仓库根目录**），等待 Sync / ohpm 依赖拉取完成。
2. `File > Project Structure... > Project > Signing Configs`。当前工程
   `app/build-profile.json5` 里 `"signingConfigs": []` 为空，说明尚未签过名。
3. 勾选 **Automatically generate signature**；如果界面有 **Support HarmonyOS** 也勾上
   （官方 Hello World 流程两个都勾；API 8/9 工程才强制需要它）。
4. 点界面提示的 **Sign In**，用已实名的华为账号登录；未实名会在此处被拦下。
5. 保持真机已连接（自动签名会把设备 UDID 注册进调试 Profile），等待 IDE 自动生成
   调试证书 / Profile 并回填配置，然后点 **OK**。
6. 验证：`app/build-profile.json5` 的 `signingConfigs` 不再为空；右上角设备下拉能选到真机；
   点 **Run**（Windows `Shift+F10`），控制台出现 `Launch ability succeed` 即成功。

> 证书、私钥、`.p12`、`.cer`、`.csr`、`.p7b` 和本机个人路径**绝不提交仓库**（#11 明确要求）。
> `.gitignore` 已忽略 `*.p12/*.cer/*.csr/*.p7b/*.jks/*.keystore`，自动签名产物通常在
> `%USERPROFILE%\.ohos\config\`，不要手动拷进工程。
> 失败排查顺序：本机时间是否 UTC+8 → 账号是否实名 → `hdc list targets` 是否有 UDID →
> 手机是否联网 → 包名 `com.example.campusagent` 是否与 AGC 已有 Profile 冲突 → 是否只连了一台设备。

### 5.3 Android 设备（不需要华为账号）

## 6. 构建与安装（第 4 节通过后我来做）

在仓库根目录（或工作副本 `E:\arkuix-campus-agent-C`）执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-native.ps1 -Platform HarmonyOS
powershell -ExecutionPolicy Bypass -File .\scripts\build-native.ps1 -Platform Android
```

脚本在 `app/` 里调用官方命令 `ace build hap --debug` / `ace build apk --debug`，并要求产物存在：

| 平台 | 产物目录 | 产物 |
| --- | --- | --- |
| 鸿蒙 | `app\entry\build\` | `*.hap` |
| Android | `app\.arkui-x\android\app\build\` | `*.apk` |

安装运行可用 DevEco 的 Run 按钮，或命令行：

```powershell
cd app
ace devices
ace run                       # 编译并在已连接设备上运行
# 或手动安装
& 'E:\DevEcoStudio\sdk\default\openharmony\toolchains\hdc.exe' -t <UDID> install <hap路径>
& 'E:\arkui-x-toolchain\android-sdk\platform-tools\adb.exe' install -r <apk路径>
```

**已知风险**：`app/.arkui-x/android/app/libs` 为空，Android 构建需要 ACE 先生成 ArkUI-X 运行时
库与 ArkTS 产物；若 `ace build apk` 报缺库，按 ACE 输出执行 `ace build` 的前置步骤再重试，
并把日志贴给我，我按报错定位。#5 要求把命令、日志、产物路径和源码提交一起记录。

## 7. 装好之后按什么顺序验收

先平台后业务，避免把环境问题误判成功能问题：

1. **#5**：两端都能安装并启动，登记设备/系统/SDK 版本与构建日志。
2. **#6**：按[C模块-设备验收与失败处理](C模块-设备验收与失败处理.md)第四节，两端各跑一遍
   真实文本对话、第二轮上下文、工具闭环，以及断网 / 无效密钥 / 超时三类失败反馈。
3. **#7**：两端各跑一遍「多轮 → 彻底退出 → 重开 → 回看 → 删除 → 再重启」，并验证损坏文件保护。
4. 之后才是 B 的 #8 页面、D 的 #9 语音、A 的 #10 Agent 演示，最后 #11 汇总材料。
   语音 ASR 必须真机（模拟器不支持 `speechRecognizer`）。

## 8. 常见坑

| 现象 | 处理 |
| --- | --- |
| `ace` 不在 PATH | 只给当前终端加 `<ArkUI-X>\24\arkui-x\toolchains\bin`，别改系统 PATH |
| `ace check -v` 缺 iOS 项 | 不影响鸿蒙/Android，忽略 |
| `hdc list targets` 为 `[Empty]` | 换数据线、重新点「允许 USB 调试」、确认驱动 |
| 真机装 HAP 报签名错误 | 重做自动签名，确认设备 UDID 已注册、账号已实名 |
| 装不上提示版本不兼容 | 核对设备 API 是否 ≥ 24，必要时调整 `compileSdkVersion` 并由平台负责人统一记录 |
| Android 构建缺 `libs` | 先让 ACE 生成运行时库，勿手动塞第三方包 |
| 应用内联网失败 | 检查 `module.json5` 的 `ohos.permission.INTERNET` 与 AndroidManifest 的 `INTERNET` 权限 |
| 密钥泄露风险 | 密钥只在应用运行时设置页输入，不写 `.env.local` 之外的文件、不进截图与日志 |
