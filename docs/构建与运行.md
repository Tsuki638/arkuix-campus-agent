## 1. 共享逻辑开发

使用 Node.js **22.13 或以上**；本机实际版本用 `node --version` 查看。无外部 npm 依赖。

```powershell
Set-Location 'C:\Users\Administrator\Desktop\arkuix-campus-agent'
npm.cmd run demo
npm.cmd run check
```

`scripts/compile-core.mjs` 读取应用实际使用的 `.ts` 源码，只为 Node 检查剥除类型并输出到忽略的 `.generated/core/`。这些产物不参与移动端交付。该检查不检查 TS 类型，也不编译 `.ets`；移动端仍需使用 DevEco/ArkTS 工具链。

## 3. 生成官方工程壳，保留共享代码

在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\initialize-arkuix.ps1
```

执行策略参数只作用于启动的 PowerShell 进程，用于执行本仓库的本地开发脚本。脚本调用 `ace create CampusAgent`。交互参数建议：

- 工程名 `CampusAgent`。
- 包名 `com.example.campusagent`，团队后续可统一调整。
- runtimeOS 选 **HarmonyOS**，与课程鸿蒙目标匹配。
- Compile SDK 选择团队已安装且与 ArkUI-X 匹配的版本。
- 若当前版本询问跨平台目标，选默认 Android+iOS 以保留 DevEco 支持；iOS 仅保留模板，不要求在 Windows 构建。

官方模板先生成到 `.generated/native-bootstrap/CampusAgent/`，脚本只把 `app/` 缺失的工程文件补入，保留已有页面、Agent 和接口。若初始化中途失败，脚本会保留暂存目录供检查，不自动删除。

生成后用 DevEco Studio 打开 **`app/`**。应出现：

```text
app/
├── .arkui-x/
│   ├── android/                 # Android 宿主，由平台工程负责人维护配置
│   ├── ios/                     # 若模板提供，当前不要求交付
│   └── arkui-x-config.json5
├── AppScope/
├── entry/
│   ├── src/main/module.json5
│   └── src/main/ets/             # 本仓库原有共享业务和 UI
├── hvigor/
├── build-profile.json5
├── hvigorfile.ts
└── oh-package.json5
```

检查 `.arkui-x/arkui-x-config.json5` 标记 `crossplatform: true` 且 modules 包含 `entry`；确认 Ability 加载 `pages/Index`。以生成模板为准保留 SDK 专有字段，不覆盖成其他版本的构建配置。结构依据 [ArkUI-X 官方工程说明](https://github.com/arkui-x/docs/blob/master/zh-cn/application-dev/quick-start/package-structure-guide.md)。

初期直接编译已有共享代码。若选定 SDK 对纯 `.ts` 模块有不同约束，平台工程负责人根据编译诊断调整兼容语法并保持同一份源码，不在 Android 宿主复制 Agent。

## 4. 确认 API、权限和签名

当前适配器使用 `@ohos.net.http` 和 `@ohos.file.fs`。平台工程负责人需按团队所选 SDK 的跨平台支持清单检查接口及模块打包配置，并在 Android 实测网络及文件读写；文档支持不等于本项目已完成设备验证。

网络：在 `entry/src/main/module.json5` 的 `module.requestPermissions` 中加入/合并：

```json
{"name":"ohos.permission.INTERNET"}
```

Android 的宿主 `AndroidManifest.xml` 需包含：

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

语音：鸿蒙实现接入后，你按选定 ASR/TTS API 补齐麦克风权限、用途说明与运行时授权；拒绝授权时保留文本路径。不要把未经验证的鸿蒙专有 Kit 直接导入跨端共享业务。

签名：在 DevEco 的 Signing Configs 中配置合法的开发签名或自动签名，证书、私钥和本地路径不提交仓库。Android debug 使用本机开发配置。

## 5. 模拟模式与真实模型接入

默认 `createDeviceRuntime(context)` 使用 **模拟模型 + 本地文件历史 + 语音未接入**。模拟模型接受分轮 JSON 输入，例如先发送 `{"goal":"复习高数"}`，再发送 `{"days":3,"minutesPerDay":90,"tasks":[{"name":"极限","minutes":60}]}`。同一会话继续发送 `{"minutesPerDay":60}` 会保留其余条件并重新计算。

旧的 `目标|天数` 格式仍可预填这两项，随后必须补充每日可用时间和任务耗时；没有虚构默认任务。这些固定格式只用于离线联调，不等同于自然语言理解。四轮短期演示运行 `npm.cmd run demo:study`。主 `npm.cmd run demo` 展示新产品的访谈、阶段计划、排期、模拟日历确认与反馈，见 [A 实现与交接](Agent学习方向与行动规划说明.md)。

设备装配新增第四个可选参数 `calendar`：`createDeviceRuntime(context, settings, speech, calendar)`。由平台工程注入真实 CalendarPort；未注入时日历明确不可用。业务仓库独立使用 `campus_agent_learning_v1.json`，不能将内存端口演示计入双端日历或持久化验收。

共享聊天页现在会先调用 `createPlatformSpeech(context)`，再将语音服务注入上述装配点；支持语音的鸿蒙设备可进入识别与播报流程。语音负责人可以先打开已准备的 `.generated/speech-demo/` 自测工程，完整操作见[语音开发与联调](语音开发与联调.md)。该工程已完成 API 24 原生编译和未签名 HAP 打包，设备语音与真实模型闭环仍待验证。

C 先确认所选云模型支持当前协议，再由 B 在设置页获取运行时配置，并调用：

```typescript
// settings: ModelSettings，来自运行时输入，不要把真实密钥硬编码到此处。
// speech: createPlatformSpeech(context) 创建的 SpeechService；未提供时使用不可用适配器。
const runtime = createDeviceRuntime(context, settings, speech);
```

`settings` 必须有 `endpoint`（完整 HTTPS `/chat/completions` 地址）、`model`、`apiKey`。无需固定厂商；不兼容此协议时由 C 新增 `ModelClient` 实现。某些模型要求额外配置思考模式等参数，按厂商官方说明补齐。

适配器通过 `OhosJsonTransport` 发出真实请求。模型设置 UI 已接入，地址、模型名称和密钥在页面填写；密钥不持久化。C 的验证说明记录了 10 月 29 日的 Node 真实调用，当前整合尚未补充设备侧真实调用证据；供应商参数及设备调用验证由 B/C 继续联调。可参考 [Model Studio 官方 Function Calling 文档](https://www.alibabacloud.com/help/en/model-studio/qwen-function-calling)。

## 6. 分别构建与安装

完成上述配置后，在仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\build-native.ps1 -Platform HarmonyOS
powershell -ExecutionPolicy Bypass -File .\scripts\build-native.ps1 -Platform Android
```

脚本在 `app/` 中分别执行官方命令 `ace build hap --debug` 和 `ace build apk --debug`。实际产物路径以 ACE 输出为准，并记录到交付说明。连接设备后可在 `app/` 下使用：

```powershell
ace devices
ace run
```

这些命令及签名规则来自 [官方 ACE Tools 命令说明](https://github.com/arkui-x/cli/blob/master/README.md)。如果所装 SDK 的命令选项有差异，以该版本 `ace help` 为准。
