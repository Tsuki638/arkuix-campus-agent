# 前后端工程架构与迁移

ArkUI-X 客户端位于 `frontend/arkuix/`，Java Spring Boot 服务位于 `backend/`。两端通过 `contracts/openapi.yaml` 约定 HTTP 业务接口。原有课题方向、历史分工和验收记录见 [原项目说明](原项目说明.md)。

## 功能边界

| 功能 | Java 后端 | ArkUI-X 客户端 |
| --- | --- | --- |
| 账号 | 注册、密码校验、设备会话及账号数据隔离 | 登录界面、会话恢复、退出与同步入口 |
| 聊天 | 会话、模型调用、上下文和摘要、工具编排、持久化 | 对话输入、格式化展示、处理状态 |
| 学习计划 | 生成规则、计划与任务、完成状态及打卡记录 | 计划列表、任务操作、进度展示 |
| 系统日历 | 草案校验和修订、写入意图、设备回执 | 用户预览确认、设备权限和系统写入 |
| 语音 | 接收识别文字、返回可播报回复 | 录音、识别、播报、停止 |
| 模型配置 | 默认凭据、服务商协议、可用接口配置 | 设置界面和本次运行的模型选择 |

## 接入和数据导入

使用 `ARKUI_BACKEND_URL` 和 `npm.cmd run prepare:model` 生成 Java 模式的客户端配置，再从 DevEco Studio 构建。各设备使用同一个 HTTPS 服务地址和账号，Java 根据会话令牌识别账号与设备。历史会话、计划、打卡及草案使用同一账号的数据文件。

用户在旧设备的「账号与同步」确认导入，服务端按业务 ID 合并已有会话、计划、打卡和草案，优先保留当前账号记录与旧服务端工作区中的记录。导入可安全重试，旧记录只关联一个账号，设备原始文件和旧工作区文件会保留。

启用 Java 模式后，正常聊天经工作区接口提交，页面轮询生成和执行状态。Java 先保存用户输入，即使模型失败也能恢复历史。同一请求 ID 的重发沿用原处理结果。工具调用和对应结果成批保存。

日历工具生成待确认草案。用户在预览页确认后，设备逐项向 Java 提交写入意图，再查询或创建系统事件。系统写入结果未能确认时，同一设备会按稳定日程标识查询并重试，然后把实际结果写入草案和对话。

Java 文件持久化面向单实例联调，启动时由 `APP_DATA_DIRECTORY` 指定目录。服务端默认监听本机回环地址，设备联调时使用设备实际可连接的地址。原有端内模式可通过留空 `ARKUI_BACKEND_URL` 使用。

## 开发与验证

运行 `npm.cmd run check` 验证客户端逻辑，运行 `npm.cmd run test:backend` 验证 Java 接口、消息持久化、历史导入、工具调用、打卡和日历确认流程。启动服务后运行 `npm.cmd run verify:backend` 可检查前后端基本连接。真机语音、日历权限和平台能力按 [验收清单](验收清单.md) 验证。
