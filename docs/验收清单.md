## 产品方向验收（真实服务与双端待验证）

本项目首版目标为“方向访谈 → 路径选择 → 阶段计划 → 日程预览与确认 → 写入日历 → 进度反馈与调整”。A 的共享业务已实现并有 Node 回归；以下整体验收仍需 B/C/D 完成页面、真实模型、平台及设备证据，保持未勾选。

共享逻辑检查涵盖：两个入口与访谈缺项、阶段任务/依赖/时间、冲突与截止日期、确认前零写入、取消/旧版本/过时预览、部分失败/核对重试、已完成/过去日程保护、损坏数据、进度与约束保留、删除与确认并发。命令及接口见 [A 实现与交接](Agent学习方向与行动规划说明.md)。

- [ ] 考研/就业入口可用，渐进收集基础与时间条件；信息不足时先澄清。
- [ ] 展示候选路径与推荐理由，用户能选择或修改；方向不明确时能安排短期体验任务。
- [ ] 生成两到四周的阶段任务，并细化未来一周日程；任务包含内容、预计耗时与完成标准。
- [ ] 排期符合用户提供的可用时段与任务依赖；授权读取日历后能检查已有日程冲突。
- [ ] 应用内计划书与任务列表可回看，计划、进度及日程 ID 映射重启后能恢复。
- [ ] 双端写入前均可预览并确认；未确认时不执行写入，拒绝权限时仍保留应用内计划。
- [ ] 双端可验证系统日程创建结果，保存关联 ID；重试不重复创建，部分失败逐项反馈。
- [ ] 用户反馈完成或未完成后可重新排期，预览确认后仅更新本应用创建的关联日程。

## 推荐演示主线

以下为目标演示流程，需在相关功能实现后验证：

1. 鸿蒙新建会话，用户提出“想为考研或就业做准备，但还没明确学习方向”。
2. 助手逐步了解基础、兴趣和可用时间，展示候选路径及理由；用户选定一条路径。
3. 生成阶段学习计划与未来一周的日程，展示任务内容、预计耗时与完成标准。
4. 用户修改一个时间约束，预览并确认后写入系统日历，打开系统日历核对结果。
5. 用户反馈一个任务未完成，助手给出调整方案；确认后更新本应用创建的后续日程。
6. 使用鸿蒙语音提出后续问题，收到真实模型响应并播报。
7. 关闭再打开应用，回看历史与计划；验证删除会话重启后仍生效。
8. 在 Android 展示同一共享 UI、真实模型文本对话、日历写入及重启后的数据。
9. 展示一次权限拒绝或工具失败的反馈，并说明两端核心代码来自同一个 `entry`。
