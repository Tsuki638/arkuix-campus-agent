## 联调时逐项记录

- [ ] 四人的 DevEco/SDK/ACE/JDK 组合一致，版本已登记。
- [ ] 官方 ArkUI-X 工程生成，`entry` 标记为跨端模块。
- [ ] 鸿蒙安装启动成功，记录设备、系统与包路径。
- [ ] Android 安装启动成功，记录设备、系统与包路径。
- [ ] 鸿蒙文本真实模型调用成功。
- [ ] Android 文本真实模型调用成功。
- [ ] 第二轮可以使用第一轮的信息，或可展示实际工具调用闭环。
- [ ] 工具参数错误、模型超时/限流、执行上限有可理解的反馈。
- [ ] 鸿蒙麦克风授权成功，完成 ASR → 模型 → TTS。
- [ ] 鸿蒙拒绝权限仍可使用文本；停止/离开页面能释放语音资源。
- [ ] 鸿蒙会话重启可回看、可删除，删除结果重启后仍生效。
- [ ] Android 会话重启可回看、可删除，删除结果重启后仍生效。
- [ ] 会话损坏或存储失败时不静默覆盖历史。
- [ ] 密钥不出现在源码、聊天历史、日志及演示截图中。
- [ ] 一页架构、Agent 流程及失败处理、依赖来源已同步至最终实现。
- [ ] 演示材料覆盖两端及鸿蒙语音，并附安装包或课程允许的完整运行说明。

## 推荐演示主线

1. 鸿蒙新建会话，提出一个缺少信息的真实场景需求。
2. 助手澄清，用户补充条件，展示工具执行状态和任务结果。
3. 使用鸿蒙语音提出后续问题，收到模型响应并播报。
4. 关闭再打开应用，回看之前的任务；删除一条会话。
5. 在 Android 展示同一共享 UI、真实文本对话、重启后的历史和删除。
6. 简要展示一次失败处理，并说明两端核心代码来自同一个 `entry`。

## 基线之后的加分优先级

先完善场景价值、页面美观、空态/错误反馈和录音状态，再按时间考虑 Agent 状态恢复、Android 语音、多模型或 RAG。iOS 为选做，不作为四人首轮开发依赖。
