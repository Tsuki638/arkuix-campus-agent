# 鸿蒙语音开发与联调

语音基础实现记录：2026-10-29；工程整合更新：2026-11-09。当前可用 DevEco 打开正式 `app/` 工程，整合源码的未签名 HAP 构建已通过；自测工程仍可用于单独诊断，鸿蒙真机和真实云模型语音流程待验收。

模拟器能力核对（2026-11-10）：华为官方说明，当前 `speechRecognizer` 不支持模拟器调试，系统 ASR 的最终验证需要兼容真机；TTS 在 6.0.0（API 20）及之后的模拟器上可测试，仍需核对镜像和语音资源。没有真机时，先做页面、文本对话、计划/历史和模拟语音端口联调；ASR 引擎在模拟器初始化失败不能直接判定为项目代码错误。

依据：[初始化语音识别引擎报错](https://developer.huawei.com/consumer/cn/doc/harmonyos-faqs/core-speech-kit-troubleshooting-0001/)、[新版模拟器 TTS 支持说明](https://developer.huawei.com/consumer/cn/doc/architecture-guides/neworderspeaker-0000002719079580/)。

## 你的交付范围

当前职责：你负责语音模块，成员 A 负责 Agent，成员 B 负责 UI，成员 C 负责模型与数据。跨端工程、日历适配和构建打包的负责人待团队明确。

语音部分的完整流程为：用户点击语音输入 → 申请麦克风权限 → 中文 ASR → 将识别文本交给现有 Agent → 显示回复 → TTS 播报。还需要处理拒绝授权、没有识别结果、取消、超时、停止及页面退出。

ASR 是语音转文字，TTS 是文字转语音。语音负责人交付语音能力及接入，模型负责人提供真实模型配置，UI 负责人维护最终交互。先用现有模拟模型开发，无需等待模型密钥。

## 现在按这个顺序做

### 1. 打开已准备的语音工程

在 DevEco Studio 选择 **File → Open**，打开：

```text
D:\huawei\.generated\speech-demo
```

等待工程同步完成。此目录已包含 API 24 配置、麦克风权限说明、自测页和共享聊天页；不需要 API Key，也不需要 Android SDK。

要同步后续仓库源码，在仓库根目录重新执行：

```powershell
cd D:\huawei
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-speech-demo.ps1
```

脚本从 `.generated/environment/dev-environment.json` 找到本机已验证的 `D:\HarmonyDev\SpeechEnvCheck24`，读取它的工程骨架，保留原工程。其他电脑可指定同版本官方空工程：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\prepare-speech-demo.ps1 -TemplateProject 'D:\你的官方空工程'
```

只编辑 `app/entry/src/main/ets/` 中的正式源码，然后重新执行脚本；生成目录中的源码会被更新。工程配置与本地签名设置保留。`.generated/` 已被 Git 忽略。

### 2. 启动模拟器并运行

在 DevEco 的设备管理器启动兼容此工程 API 24 的鸿蒙模拟器，运行配置选择 `entry`，目标选择该模拟器，再点击 Run。

如果尚无虚拟设备，先通过设备管理器创建并启动兼容镜像。若安装时要求签名，按 DevEco 提示在项目 Signing Configs 中完成本地调试签名；命令行生成的 HAP 当前未签名。

这次构建时 `hdc list targets` 未显示已连接目标，因此尚未替你安装或操作模拟器。

### 3. 先测试播报

打开后应显示“鸿蒙语音自测”。记录页面中的 ASR/TTS 系统能力，然后点击 **“2. 播报上方文字”**。

默认测试文字是“你好，我是学习规划助手。语音播报测试开始。”。听到播报，且页面最终显示“播报完成”，才能记录本次 TTS 成功。再测试播报途中点击“停止语音”。

若没有声音，先检查电脑、模拟器音量与音频输出；若显示能力未声明或引擎错误，记录页面提示及系统错误码。系统能力已声明也不保证离线语音资源与服务可用。

### 4. 使用兼容真机测试识别；无真机时先模拟接口联调

在兼容真机上点击 **“1. 开始中文识别”**，首次弹出权限窗口时允许麦克风，待权限窗口关闭后说一句简短中文，例如：

> 我每天晚上有一个小时，想准备计算机专业考研。

说完稍作停顿，查看最终文本。单次采集配置为最长约 15 秒，整个权限/初始化/识别操作最多等待 30 秒。识别结束后，可点击“将识别结果用于播报”，再点击播报按钮，验证 ASR 与 TTS。

模拟器的麦克风录音能力与系统 ASR 服务是不同的能力；电脑麦克风可用不代表 `speechRecognizer` 可用。没有兼容真机时，将真实识别登记为“待真机验证”，使用项目的模拟语音端口检查结果传递、失败、超时、停止与资源释放，再用固定文本接通 Agent 和计划流程。模拟结果不能计为真实 ASR 验收。

### 5. 测试聊天连接

点击 **“3. 打开聊天联调（默认模拟模型）”**。在模拟器先输入文字，确认聊天与学习计划正常；有兼容真机后，再点击“语音输入”，说一句中文，观察是否依次出现识别、处理与播报状态。

默认回复来自 `MockModelClient`。这一步可以检查“语音 → Agent → 模拟回复 → 播报”的连接；课程中的“真实云端模型”验收仍需下面的联调。

### 6. 与模型、UI 负责人联调

当前聊天初始化代码为：

```typescript
const speech = await createPlatformSpeech(context);
const runtime = createDeviceRuntime(context, undefined, speech);
```

模型负责人和 UI 负责人提供运行时 `ModelSettings` 后，将第二个参数替换成该配置：

```typescript
const runtime = createDeviceRuntime(context, settings, speech);
```

`settings` 包含完整 HTTPS endpoint、model、apiKey，由运行时配置获得。保持语音驱动与模型凭据分离。先验证真实模型的文字请求，再做识别 → 真实回复 → 播报。

交接给 UI 负责人时说明：`recognizeOnce()` 只返回最终文字；使用原有 `agent.send`；`speak()` 等到实际播报完成才结束；停止会使正在等待的操作以 `SPEECH_CANCELLED` 结束。当前 UI 已接入最小流程，可由 UI 负责人继续调整布局。

## 合入正式团队工程的配置

当前 `app/` 已生成官方工程壳并合入下列权限、资源和页面配置，默认进入共享聊天页。以下内容供其他环境迁移核对；独立自测工程继续用于诊断正式共享源码。

在 `entry/src/main/module.json5` 的 `module.requestPermissions` 中合并麦克风用途声明，保留已有权限：

```json
{
  "name": "ohos.permission.MICROPHONE",
  "reason": "$string:microphone_reason",
  "usedScene": { "abilities": ["EntryAbility"], "when": "inuse" }
}
```

在模块资源的 `base/element/string.json` 中增加：

```json
{"name":"microphone_reason","value":"用于将你的语音转换为学习规划问题"}
```

真实模型请求还需要已有文档中的 `ohos.permission.INTERNET`。

本机 API 24 的 `.arkui-x/arkui-x-config.json5` 使用以下结构；`ignoreCrossPlatform` 位于 **buildOption 内部**。已通过本机 SDK schema 及构建验证：

```json
{
  "crossplatform": true,
  "modules": ["entry"],
  "buildOption": {"ignoreCrossPlatform": true}
}
```

该选项将非跨平台 API 检查降为警告。语音专有依赖只放在驱动内，并由工厂在 Android/iOS 上跳过加载。该设置不能作为 Android 兼容性的证据，平台负责人仍需构建 APK 并验证文本主流程。

如需保留语音自测页，在 `main_pages.json` 中注册 `pages/SpeechDiagnostics` 和 `pages/Index`；正式首页仍可由 Ability 加载 `pages/Index`。自测工程已自动完成上述配置。

## 关键行为与排错

| 情况 | 预期行为 |
| --- | --- |
| 首次识别 | 弹出麦克风授权；允许后创建识别引擎 |
| 拒绝权限 | 提示 `SPEECH_PERMISSION_DENIED`，不启动录音；聊天文本仍可发送 |
| 识别期间取消 | 等待中的 Promise 结束；迟到的权限/识别结果不再触发提交 |
| 无语音或仅有中间结果 | 返回 `SPEECH_NO_RESULT`，不发送未经确认的文本 |
| 无最终回调 | 识别最多等待 30 秒；播报最多等待 120 秒；超时结束并释放引擎 |
| 连续点击 | 操作互斥，返回 `SPEECH_BUSY`，不启动第二个录音/播报 |
| 退出、切后台或页面隐藏 | 停止语音，过期的识别结果不发送；等待模型的旧语音轮次不再自动播报 |
| TTS 失败 | 保留已生成文字，显示语音错误；可继续文本聊天 |
| 超过 10000 字的回复 | 本次播报返回长度错误，保留文字；首版未实现分段长文朗读 |
| 系统能力或资源缺失 | 页面显示不可用或系统错误码；更换支持能力的镜像/设备后复测 |

引擎创建失败保留系统错误信息，ASR/TTS 回调错误显示对应数值码。避免在日志中打印录音、完整识别文本或模型密钥。

原生构建中的 Core Speech Kit 跨平台警告来自鸿蒙专有能力，工厂已限制加载平台；当前仍有部分 API 异常处理提示及旧页面上下文 API 的弃用提示。构建成功不能替代设备运行验证。
