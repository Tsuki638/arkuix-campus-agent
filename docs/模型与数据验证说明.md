# 模型与数据验证说明（成员 C）

本文件说明成员 C（模型与数据服务）负责部分的实现范围、如何在本地验证，以及哪些内容仍需实机联调。

## 一、本次实现的范围

| 模块 | 文件 | 作用 |
| --- | --- | --- |
| 上下文裁剪 | `app/entry/src/main/ets/services/model/ContextTrimmer.ts` | 按字符预算裁剪历史，保留 system 消息，按“assistant 工具请求 + 其 tool 结果”整组丢弃最早上下文，绝不拆散配对。 |
| 模型适配层 | `app/entry/src/main/ets/services/model/CompatibleModelClient.ts` | 在原有工具协议映射基础上，新增 `ModelClientOptions.maxContextChars`（默认 24000），发送前裁剪；把传输/模型异常收敛为固定 `MODEL_*` 错误码，不透传供应商报文或密钥。 |
| 学习数据仓库 | `app/entry/src/main/ets/services/storage/StudyDataRepository.ts` | 用独立 key `study_data_v1` 持久化学习计划与打卡记录，写入串行化、保存快照、损坏不覆盖历史。 |
| 验证脚本 | `scripts/verify-model.mjs` | 真实模型连通性验证；缺少凭据时跳过并以 0 退出。 |
| 单元测试 | `tests/framework.test.mjs` | 新增 5 个用例覆盖错误码分类、上下文裁剪、学习数据仓库持久化与损坏保护。 |

错误码约定：`MODEL_CONFIG`（配置非法）、`MODEL_AUTH`（401/403）、`MODEL_RATE_LIMIT`（429）、`MODEL_TIMEOUT`（超时/中断）、`MODEL_HTTP`（其它非 2xx）、`MODEL_TRANSPORT`（断网/DNS）、`MODEL_RESPONSE`（响应格式不兼容）。D 的 `OhosJsonTransport` 已抛出的分类原样透传，不二次改写。

## 二、本地验证步骤

在仓库根目录（Node ≥ 22.13）执行：

```bash
npm run check   # 转换共享逻辑 + 导入检查 + 运行全部单元测试
npm test        # 只运行单元测试
```

预期结果：18 个用例全部通过，共享逻辑模块转换与导入检查通过。

真实模型联调（可选，会产生实际调用）：

```bash
MODEL_ENDPOINT="https://<你的接口>/v1/chat/completions" \
MODEL_MODEL="<模型名>" \
MODEL_API_KEY="<运行时密钥>" \
node scripts/verify-model.mjs
```

- 三个变量缺任意一个，脚本打印跳过提示并以 0 退出，不算失败。
- `verify-model.mjs` 用 Node `fetch` 复刻同一个 `JsonTransport` 端口（同样的 Bearer 头、60 秒超时、状态码分类），因为设备端 `OhosJsonTransport` 是 `.ets`，无法在 Node 直接运行。
- 脚本会发起一次带 `create_study_plan` 工具定义的请求，打印模型是走工具调用还是纯文本，并对工具调用实际执行一次。

## 三、密钥与安全

- 模型密钥只在运行时经环境变量注入，仅通过 `Authorization` 头发送，禁止写入历史、日志或提交仓库。
- 适配层与验证脚本都不打印请求头或响应全文，避免返回体中的账户信息外泄。

## 四、仍需实机/联调验收的内容

- 设备端 `FileKeyValueStore` + `OhosJsonTransport` 在鸿蒙与 Android 上的真实读写与网络行为，由 D 的适配器在选定 SDK 上验证；本仓库的 Node 文件端口检查只验证公共仓库协议，不能代替两端重启实测。
- 所选厂商模型的真实工具调用能力已于 2026-10-29 由 `verify-model.mjs` 联调确认:使用阿里云百炼(DashScope)`qwen-plus`、OpenAI 兼容 endpoint,模型正确返回 `create_study_plan` 工具调用且工具执行成功,往返通过。密钥仅经本地环境变量注入,未入库未打印。剩余待确认:所选模型的专有参数与限流表现、以及更大并发下的稳定性。
- `StudyDataRepository` 目前是轻量整份 JSON 读写；数据量扩大后由 C 迁移到数据库。
