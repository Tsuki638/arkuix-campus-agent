## 启动应用

队员获取本版代码后，可在仓库根目录切换到整合分支：

```powershell
git fetch origin
git switch codex/integrate-runnable-app
npm.cmd run check
```

用 DevEco Studio 打开仓库下的 `app/`，同步工程，配置本机调试签名后运行 `entry`。

本版已将 `compileSdkVersion` 和 `targetSdkVersion` 显式设为 `6.1.1(24)`。配置变更后点击 IDE 蓝色提示条的“立即同步”，待 `entry` 运行目标恢复，再选择模拟器并运行。

默认使用模拟模型。先发送 `复习高数|3`，应能看到工具结果；进入“学习计划”查看三项任务，标记完成，再撤销一次。退出重启后验证计划和完成状态仍在。全部学习计划独立于会话保存，删除会话保留学习计划。

点击“模型设置”，填写完整 HTTPS Chat Completions 地址、模型名称和 API Key，再点击“使用云端模型”。密钥仅驻留本次运行，不写历史、学习数据或工程配置；重启后重新输入。配置格式通过仅说明可以发起请求，实际连通性以发送消息的结果为准。可在空闲时切回离线示例。

语音输入使用同一个 Agent 入口。先独立验证识别与播报，再验证“识别 → 真实模型 → 播报”。拒绝权限、停止、切后台和页面退出也要留设备记录，详见[语音开发与联调](语音开发与联调.md)。

没有鸿蒙真机时，先用模拟器验证界面、文本模型、计划/历史和支持镜像上的 TTS，用模拟语音端口检查后续流程。当前系统 `speechRecognizer` 不支持模拟器调试，真实 ASR 及完整语音流程须由兼容真机补验。

## 检查和构建

```powershell
npm.cmd run check
npm.cmd run demo
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-native.ps1 -Platform HarmonyOS -AceCommand '你的 ACE 命令路径'
```

`npm run check` 包含 C 的 18 项基础与服务检查、12 项语音检查、4 项整合检查，共 34 项。整合检查使用模拟 HTTP 和语音端口，验证完整工具回传、计划持久化、打卡、模型切换和异常恢复。

真实模型脚本通过 `MODEL_ENDPOINT`、`MODEL_MODEL`、`MODEL_API_KEY` 环境变量接收本机配置，然后执行 `npm.cmd run verify:model`。脚本现在验证完整 Agent 工具流程和计划保存；缺少配置以退出码 2 结束，未执行云调用；失败返回 1，通过返回 0。脚本不会读取仓库外的凭据文件。

如需使用另一台电脑的同版本官方空工程补齐配置，可运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/prepare-project.ps1 -TemplateProject '你的官方 ArkUI-X 空工程目录'
```

准备脚本保留已有业务源码、工程配置和签名设置。`scripts/prepare-speech-demo.ps1` 仍可单独更新 `.generated/speech-demo/`，用于独立语音诊断。

Android 使用 `scripts/build-native.ps1 -Platform Android`，需要另行安装 SDK/JDK 并完成 ACE 配置。官方宿主的生成资源由 ACE 构建，仓库只保留宿主源码和配置。
